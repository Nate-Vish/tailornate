# /brainstorm — Explore Before Defining

Open-ended exploration. No commitments, no implementation — just thinking.

## Process

### Step 1: Capture the seed
Ask the user: "What are you thinking about?"
Listen without judging. Could be a vague idea, a problem, a technology, a business concept.

### Step 2: Explore angles
For each idea, explore:
- **The problem angle:** What pain does this solve? Who has this pain? How bad is it?
- **The solution angle:** What are 3 different ways to solve this? Which is simplest?
- **The competition angle:** Does something like this already exist? What's different?
- **The risk angle:** What's the hardest part? What could kill this idea?
- **The opportunity angle:** What happens if this works? What does success look like?

### Step 3: Challenge
Push back constructively:
- "What if you didn't build this at all — what would the user do instead?"
- "What's the version that takes 1 day instead of 1 month?"
- "Who's the first user and how do they find this?"

### Step 4: Capture
If something worth remembering emerged:
- For quick ideas → use /idea to capture
- For ideas worth developing → summarize key insights inline

### Step 5: Suggest next step

If an idea has legs:
→ "This is worth specifying. Want to run /spec to nail down the requirements?"

If still fuzzy:
→ "Want to keep exploring, or let it sit and come back later?"

If it's a dead end:
→ Say so honestly. "I don't see the value here because [reason]. Want to explore something else?"
